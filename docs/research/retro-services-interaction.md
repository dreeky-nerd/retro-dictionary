# 레트로 모바일 서비스가 원형과 사용성을 조율한 방식

- 조사일: 2026-10-01
- 범위: 실제 iPhone 앱 4종의 공식 개발사 자료·앱스토어 설명. 아래 **제품 사실**과 **전자사전 적용 추론**을 구분한다. 앱의 인기나 성과는 판단하지 않는다.
- 질문: CASIO XD-SW6400을 우선으로, SHARP RD-9100MP·iriver D26의 당시 키 모양과 배열을 유지하면서 한국어·일본어·영어 **실제 사전**을 iPhone에서 어떻게 조작하게 할 것인가? 실물 전체 축소와 큰 현대식 6버튼 대체는 모두 제외한다.

## 전자사전에서 결정적인 차이

**확인된 프로젝트 제약:** 최신 수정 시안은 CASIO의 QWERTY, 사전 단축키, 필기 패널, 좌측 페이지·돌아가기와 우측 방향·결정 키의 상대 배치를 유지한다. LCD 세로 확대는 제안이며 확정 설계가 아니다. [원형 키 수정안](../design/original-keys-revision.md). 제품은 예시 단어 검색이 아닌 한국어·일본어·영어 실제 사전 검색이 필요하다. [프로젝트 지침](../../AGENTS.md).

**적용 추론:** iPhone 폭을 문자 키 약 10열에 나누면 키 하나가 차지할 수 있는 폭 자체가 작다. 여백·키 간격·베젤까지 고려하면 더 좁아진다. 이는 Delta의 적은 게임 버튼이나 카메라의 셔터 하나와 다르다. 반대로 폭 계산만으로 불가능하다고 단정할 수도 없다. 실제 키 모양, 각인 크기, 인접 키 오입력률, 한글 조합 입력, 일본어 입력, 후보 선택, 뜻풀이 읽기를 같은 화면에서 시험해야 한다. 보이지 않는 터치 영역을 서로 겹치도록 넓히는 방식은 오입력의 원인을 숨길 수 있다.

## 토론에 쓸 설계 가설

1. **원형 키보드는 기본 조작면으로 남긴다.** 스킨별 키 형태·행·전용 키 위치를 자료와 대조한다. 검색어 입력 → 후보 선택 → 뜻풀이 → 뒤로의 전 과정을 그 키로 수행할 수 있어야 한다. 이는 사용자 요구다.
2. **배경의 빈 공간보다 LCD와 키에 폭을 준다.** 두꺼운 장식 프레임을 줄이고, 키 배열을 바꾸지 않는 선에서 표시 크기와 자간을 따로 조정한다. LCD 세로 확대는 원형 비율 변경을 수반하므로 비교안으로 명시한다. 이는 iDOS의 화면 방향별 재배치에서 얻은 *설계 추론*이다.
3. **입력 보조는 추가 경로로 시험한다.** 원형 키를 누르다 입력창에서 iOS 키보드를 선택적으로 열 수 있는 안, 검색 후보를 활용하는 안을 각각 비교한다. 전용 사전 키·방향·결정·뒤로의 역할은 유지한다. Hipstamatic의 두 촬영 경로는 공존 가능성의 참고일 뿐 사용성 증거는 아니다.
4. **성공 기준은 감상과 입력을 함께 본다.** 실제 iPhone에서 세 언어의 짧고 긴 검색어로 오입력·수정 횟수, 후보 선택 성공, 뜻풀이 가독성, 그리고 사용자가 느끼는 기기 동일성을 관찰한다. 스킨별 차이도 따로 본다. 지금 조사만으로 특정 배치를 승인하거나 터치 사용성을 입증할 수 없다.

**당장 비교할 두 화면:** `A` 원형 키 배열 + 주변 장식 최소화 + LCD 세로 확장, `B` 같은 키 배열 + 원형 LCD 비율 유지 + 입력 중 후보/뜻 화면 배치 변경. 두 안 모두 큰 6버튼 UI를 포함하지 않는다. 실제 기기 화면과 터치 시험에서 **읽기와 입력이 모두 가능한지** 확인한 뒤 비율을 고른다.
