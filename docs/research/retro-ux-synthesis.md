# 레트로 감성과 터치 사용성 — 사례 조사·토론 종합

작성일: 2026-10-01. 두 Sol 에이전트의 사례 조사와 반론, 주 에이전트의 공식 자료 조사를 종합한 디자인 가설이다. 실제 앱 사용성 시험이나 성공 가능성 입증 결과가 아니다. 이번 단계에서는 새 UI·이미지를 만들지 않았다.

토론 원문: [레트로 서비스 조사](retro-services-interaction.md), [상호작용 대안과 반론](retro-interaction-debate.md). 이 종합 문서의 A/B/C는 별도 토론 문서의 문자 구분과 다를 수 있으므로 아이디어 이름으로 비교한다.

## 문제와 전제

사용자가 거부한 것은 원형 전체를 너무 작게 보여주는 방식과, 원래 키를 큰 현대식 6버튼으로 대체하는 방식이다. 원래 기기의 키 모양·배열을 사용 경험에 남기되 읽고 입력하기 편해야 한다. iOS 우선, 한국어·일본어·영어 사전이며 번역기가 아니다.

‘잘 보이는가’, ‘잘 누르는가’, ‘뜻풀이를 읽는가’는 각각 다른 문제다. 글자를 키워도 터치 면적은 늘지 않는다. 자판 높이를 늘려도 10열의 가로 피치는 늘지 않는다. 버튼을 장식으로 만들고 실제 입력을 모두 시스템 키보드로 보내면 원래 조작 경험이 약해진다.

## 토론에서 남긴 후보

### A. 같은 기기의 작업 부위에 가까이 다가가기 — 기본 후보

1. 처음에는 실제 기기의 닫힌 모습과 개폐 경험을 보여준다.
2. 검색 입력을 시작하면 동일한 자판이 정면의 가까운 위치로 이동한다. 같은 키캡·각인·배열·눌림을 유지한다.
3. 입력 중에는 LCD 전체 뜻풀이 대신 검색어와 사전 후보에 필요한 공간을 둔다. 필기판과 주변 장식은 화면 밖으로 잠시 벗어날 수 있다.
4. 타이핑을 시작한 뒤에는 키의 위치와 크기를 고정한다. 손가락 아래에서 다음 글자를 예측하며 키를 재배치하지 않는다.
5. 일부 철자만 입력해도 사전에 실제로 있는 표제어 후보를 선택할 수 있게 한다. 필요하면 끝까지 입력한다. ‘두세 글자면 모든 검색 완료’라고 약속하지 않는다.
6. 결과를 고르면 같은 LCD에 가까이 다가가 읽는다. 일반 흰색 사전 앱으로 교체되는 느낌을 피한다.

원형 보존 관점의 반론: 일부 부품이 동시에 보이지 않으므로 ‘기기 전체를 항상 보여야 한다’는 조건과는 양립하지 않는다. 이는 제안이며 사용자 승인으로 취급하지 않는다.

사용성 관점의 반론: 앞선 이미지에서 이미 화면 폭을 대부분 사용했다면 추가 확대의 가로 이득은 작다. 작업면 집중은 글자 가독성과 공간 경쟁을 개선할 수 있지만 작은 키의 근본 해결을 보장하지 않는다. 후보 검색은 타건 횟수를 줄이는 보조 수단이며 오입력 자체를 없애지 않는다.

### B. 원래 필기 패널을 크게 펼치기 — CASIO 차별화 후보

CASIO의 하단 필기 패널을 누르면 같은 테두리와 화면 질감을 가진 입력면이 넓어진다. 손가락으로 글자를 쓰고 인식 후보를 선택하면 본래 LCD에 검색어가 들어간다. 필요한 경우 자판 입력과 전환한다.

원래 기기에 있던 행위와 연결되고 작은 문자키를 피할 수 있다는 점에서 매력적이다. 손글씨에 익숙하거나 읽는 법을 모르는 일본어 한자를 찾을 때 유용할 가능성이 있다. 그러나 적은 획의 영단어 타이핑보다 느릴 수 있고, 한글 음절·한자 인식 오류, 지우기·다시 쓰기, 인식 결과 확인이 새 병목이 된다. 일본어·한국어·영어에 같은 효과가 난다고 가정하지 않는다.

이 동작은 패널을 원래 크기로 사용하는 정확한 복제가 아니라 앱에서 추가한 확대 동작이다. 필기 패널이 없는 SHARP·D26에 같은 부품을 원형인 것처럼 추가하지 않는다.

### C. 작은 키를 누른 채 확인하고 놓아 확정 — 정밀 보조 후보

빠른 탭은 기존대로 입력한다. 정확한 선택이 어려울 때 누르고 있으면 손가락에 가려지지 않는 위치에 주변 키의 확대 보기를 띄운다. 접촉을 유지한 채 선택점을 조금 조정하고 손을 떼면 확정한다. 실제 키 배열은 움직이지 않는다.

참고 근거: Shift 연구는 가려진 영역을 외부 말풍선에 보여주고 손가락을 떼어 선택하는 기법으로 작은 표적의 오류를 줄이는 결과를 보고한다. [연구자 프로젝트](https://patrickbaudisch.com/projects/shift/index.html), [CHI 2007 논문](https://www.patrickbaudisch.com/publications/2007-Vogel-CHI07-Shift.pdf).

이 연구는 현대 iPhone의 연속 한글·일본어·영어 입력이나 우리 제품의 검색 속도를 입증하지 않는다. 확대창을 보는 시선 이동, 손가락 미세 조정, 매 글자 대기 때문에 피로할 수 있다. 모든 타건에 강제하지 않는다. 정밀 운동이 어려운 사용자의 유일한 입력 경로가 되어서도 안 된다.

### 제외한 방향

- 키 6개로 단순화: 사용자 거부, 기기 식별성이 사라짐.
- 키를 누를 때마다 자판 전체가 움직이거나 돋보기처럼 휘어짐: 다음 글자를 누를 위치가 바뀌는 위험.
- 자판 좌우를 계속 스크롤: 표제어 하나를 입력하면서 탐색과 입력이 반복될 위험.
- 매 검색마다 가로 회전 강제: 화면 폭은 얻지만 반복 사용과 한 손 조작 비용이 큼.
- 소리·햅틱만 강화: 감각은 보완하지만 가독성과 타건 정확도를 해결하지 않음.
- AI가 단어·뜻을 추측해 확정: 잘못된 철자나 인식 결과를 숨길 수 있고 사전이라는 제품 원칙과 충돌. 후보는 사용자가 선택하고 뜻은 사전 원문을 조회해야 함.

## 제안 결론과 검증

한 개의 멋진 이미지로 결론내리지 않는다. CASIO 하나로 A와 B를 비교하고 C는 A의 선택적 보조로만 시험한다. 기본 타이핑·필기 중 무엇이 주인공인지는 결과에 따라 정한다.

간단한 비교 과제:
- 짧은 단어, 긴 단어, 비슷한 철자의 단어, 읽는 법을 모르는 한자, 목록에서 선택, 긴 뜻풀이 읽기.
- 참가자가 실제로 사용하는 언어로 시험하고 일본어 사용자에게만 일본어 변환 과제를 평가한다.
- 같은 단어를 반복해 외우는 효과를 줄이도록 조건별 동등 난도의 단어를 바꿔 제시한다.
- 기존 축소 자판, A, A+C, B의 검색 완료 시간·수정 횟수·도움 요청·후보 오선택을 비교한다.
- 처음 한 번의 감탄과 10분 반복 사용 후 계속 쓰고 싶은 정도를 따로 묻는다.
- 원형 기기의 느낌이 남는지 묻고, 특히 키를 실제로 누르고 있다고 느끼는 장면을 확인한다.

폐기 신호: A가 기존 축소안보다 입력 오류와 검색 시간이 개선되지 않으면 ‘확대하면 해결’ 가설을 폐기한다. C가 대부분의 글자에서 필요하거나 반복 입력을 지연시키면 기본 해법으로 채택하지 않는다. B가 인식 수정 때문에 자판보다 더 오래 걸리는 언어·과제에서는 보조 입력으로 한정한다. 통계적 성공 판정이나 전체 사용자 일반화는 별도 규모의 검증이 필요하다.

이미지와 애니메이션 비용을 더 쓰기 전에 원형 키의 모양을 유지한 최소 조작 시험으로 확인한다. 기기 원음이 확보되기 전 임시 음원을 원음으로 부르지 않는다.
