# 현대적 레트로 전자사전 — 콘셉트 검토

초안일: 2026-09-30. 사용자 요구와 설계 제안을 구분한 검토 문서다. 승인된 상세 설계나 구현 계획은 아니다.

2026-10-01 변경: 첫 기준 기종은 CASIO XD-SW6400이며 SHARP RD-9100MP·iriver D26 스킨 시안을 구성했다. 사용자가 MP3 같은 불필요한 기능을 제외하자고 범위를 조정했다. 아래 전체 기능 재현 요구와 기종 미선정 표현은 초기 기록이며 최신 범위는 [상세 시안](design/mockup-spec.md)과 AGENTS.md를 따른다.

## 중심 문장 — 제안

**손안의 오래된 전자사전, 안의 언어는 오늘까지.**

익숙한 기기의 몸체·메뉴·소리·화면을 다시 사용하면서, 실제 사전 데이터는 계속 갱신한다. 번역 결과를 생성하는 앱이 아니라 출처가 있는 사전을 조회하는 앱이다.

## 사용자가 정한 방향

- iOS 네이티브를 먼저 만들고 Android 네이티브로 확장한다.
- 한국어·일본어·영어를 지원한다. 사용자 언어의 사전이 기본이고 요청 시 한국어·영어 풀이를 추가한다.
- 휴대폰 언어에 따라 해당 문화권의 전자사전을 처음 보여 주고, 이후 스킨을 바꿀 수 있다.
- 한 번 터치하면 기기가 열리는 모션을 보여 준다.
- 실제 기기의 버튼 소리와 디스플레이 느낌, 현실적인 애니메이션을 구현한다.
- **특정 기종의 계산기·학습 메뉴 등 부가 기능까지 원형 그대로 재현한다.** 핵심 사전 기능만 구현하는 것으로 대체하지 않는다.
- 사전은 지속적으로 업데이트하며 신조어도 포함한다.
- 자산 생성이 필요하면 Higgsfield의 활용 목적을 알린다. 현재 생성이나 토큰 사용을 요청한 것은 아니다.

## 접근 방식 비교 — 추천은 두 번째

| 접근 | 장점 | 제약 |
|---|---|---|
| 기기 전체를 그대로 복제 | 원래 메뉴와 동작의 일관성이 가장 높음 | 고정 콘텐츠까지 보존하면 최신 사전 요구와 충돌. 원본 데이터 확보 필요 |
| 원형 기기 + 별도 확장 메뉴 | 원래 기능을 충실히 제공하면서 최신 데이터와 휴대폰 편의를 더할 수 있음 | 원래 기능과 추가 기능의 경계를 명확히 설계해야 함 |
| 현대 사전에 레트로 외형만 적용 | 빠른 검색과 단순한 개발 범위 | 부가 기능까지 원형대로 구현하라는 요구를 충족하지 않아 추천하지 않음 |

두 번째는 펌웨어 에뮬레이션을 하겠다는 뜻이 아니다. 설명서와 실물의 동작을 기준으로 네이티브 앱에 재구현하는 제안이다. 기종별 재현 범위와 데이터 권한을 확인하기 전에는 완전 재현을 약속하지 않는다.

## 첫 경험과 매일의 사용 — 제안

1. 첫 실행에서 휴대폰 언어를 초기 스킨 추천에 사용한다. 한국어·일본어·영어는 사전 지원 언어이며, 각각 하나의 국가와 동일시하지 않는다. 영어권 대표 모델과 한국 대표 모델은 추가 조사가 필요하다. 미지원 언어에는 공통 기본 스킨과 수동 선택을 제공한다.
2. 닫힌 기기를 터치하면 실제 힌지 축을 따라 열리고, 화면이 켜진다. 속도·반사·그림자와 소리가 같은 동작을 표현하도록 맞춘다.
3. 원래 메뉴, 방향키, 확인·뒤로 키로 사전과 부가 기능에 접근한다. 보이는 키는 명시된 실제 기능을 수행한다.
4. 별도 확장 메뉴에서 큰 글씨, 휴대폰 키보드, 추가 사전과 최신 신조어를 사용할 수 있게 한다. 원래 키보드도 계속 작동한다.
5. 앱 잠깐 전환 후 복귀할 때는 펼친 상태와 검색 위치를 복원하는 것을 추천한다. 새로 시작할 때의 여는 경험과 검색 도중 재진입을 구분한다. 사용자가 고른 스킨은 휴대폰 언어 변경만으로 초기화하지 않는다.

기기 외형, 앱 표시 언어, 입력 언어, 사전 풀이 언어는 독립적으로 취급한다. 일본 기기 외형을 골랐다고 한국어 사전이 사라지면 안 된다.

## 옛 기기의 제약과 현대적 편의

아래는 모든 구형 모델에 없던 기능이라는 주장이 아니다. 기준 기종을 고른 뒤 실제로 제공하던 기능과 사용성 문제를 대조한다. 구형 모델에도 복수 사전 검색 같은 기능이 존재한다.

| 개선할 제약 | 원형을 유지하며 추가할 편의 | 검증 기준 |
|---|---|---|
| 내장된 사전의 내용이 오래됨 | 원자료 개정판과 검수된 신조어를 지속 공급 | 단어의 출처·데이터 판본·확인일을 식별 가능 |
| 휴대폰에서 재현한 작은 키로 긴 검색어 입력이 어려움 | 원래 키와 별도로 시스템 키보드·붙여넣기 | 한글 조합·가나 변환·영어 입력 후 같은 검색 결과 |
| 작은 LCD의 긴 설명 읽기 | LCD를 누르면 뜻풀이를 확대 | 본체 화면과 확대 화면의 표제어·선택 상태 동일 |
| 뒤로 가거나 다른 사전으로 바꿀 때 흐름을 잃음 | 선택 위치·스크롤·검색어 복원 | 상세 화면에서 돌아오면 직전 위치 유지 |
| 매번 기다리는 기동 연출 | 신규 시작의 개폐 연출, 재진입은 상태 복원 | 검색 중 앱 전환으로 입력 내용이 사라지지 않음 |

신조어는 기본 사전과 출처·검수일을 구분한다. 모르는 단어를 그럴듯하게 생성해서 채우지 않는다.

## 디스플레이·소리·모션

**화면:** 기준 기종의 실제 해상도·글자 형태·선택 반전·LCD 색·명암을 조사한다. 흑백 문자 LCD를 선택한다면 한글·한자 표현을 위해 도트 형태를 참고한다. 숫자용 7세그먼트 표현을 모든 본문에 적용하지 않는다. LCD에 CRT 주사선·과도한 글리치를 임의로 더하지 않는다. 확대·VoiceOver·동작 줄이기는 원래 경험과 함께 사용할 수 있어야 한다.

**소리:** 기계적인 버튼 누름음과 전자적인 입력 확인음을 구분해 확보한다. CASIO XD-SR 설명서는 키를 누를 때 나는 짧은 전자음을 켜거나 끌 수 있다고 설명한다. 선택 기종도 같다고 가정하지 않고 실물을 확인한다. 실물 녹음이나 제공받은 음원의 출처·사용 조건을 기록한다. 인터넷 영상에서 추출한 소리를 배포 가능한 원본으로 간주하지 않는다. 원음 확보 전 합성 효과음을 쓴다면 임시 자산으로 표시한다. 효과음과 발음 재생은 구분하고 무음·효과음 끄기를 존중한다. [CASIO 설정 안내](https://support.casio.jp/exword/manual/XD-SR_ja/sr_series_ja/id80000254.html)

**모션:** 힌지 회전, 키의 눌림과 복귀, LCD 켜짐을 중심으로 한다. 접히는 플라스틱이 고무처럼 크게 튀는 연출은 피한다. 손가락 입력과 애니메이션을 연결하고 반복 사용을 막는 대기 시간을 만들지 않는다. 동작 줄이기 설정에는 짧은 전환을 제공한다. [Apple 모션 지침](https://developer.apple.com/design/human-interface-guidelines/motion)

## 지속 갱신 방식 — 제안

앱 업데이트와 사전 내용 업데이트를 분리한다. 공급원마다 API 조회, 다운로드 가능한 데이터 판본, 캐시·오프라인 저장 허용 범위가 다르므로 모든 사전을 통째로 내려받는다고 가정하지 않는다.

- 다운로드·저장이 허용된 사전은 판본을 관리하고 새 판본을 검증한 후 적용한다. 실패하면 기존 정상 판본으로 계속 검색한다.
- API형 사전은 서비스 조건에 따라 조회하고, 캐시 가능 기간과 저장 범위를 지킨다. 네트워크가 없을 때 사용할 수 있는 범위를 표시한다.
- 신조어는 후보 수집 → 출처·용례 확인 → 뜻·맥락 편집 → 검수 → 배포 순서를 거친다. 공급원의 수정일을 유행 시작일로 표시하지 않는다.
- 화면에 데이터 판본·최근 갱신일을 확인할 경로를 제공한다. 기능 없는 장식용 업데이트 표시를 넣지 않는다.
- 앱 실행 시 갱신 확인을 기본으로 검토하고, iOS 백그라운드 갱신은 보조로 사용한다. 실행 시점은 OS가 결정하므로 매일 특정 시간의 업데이트 완료를 보장하지 않는다. [Apple 백그라운드 전략](https://developer.apple.com/documentation/backgroundtasks/choosing-background-strategies-for-your-app)

구체적 공급원·갱신 주기·편집 담당·오프라인 수록량은 아직 미정이다. 개인 단어장의 클라우드 동기화는 별도 요구가 없으므로 추가하지 않는다.

## 기종별 완성의 정의

설명서 항목마다 원래 화면·입력·결과·예외 동작·필요한 자산·검증 근거를 기록한 기능 대조표를 만든다. 사전 검색, 단어장, 발음, 계산기, 학습 메뉴뿐 아니라 선택 기종에 실제로 포함된 기능을 빠짐없이 조사한다.

계산기는 키별 입력과 결과를, 학습은 정답 판정·진행·저장·재개를 검증한다. 단순히 메뉴가 열리는 것으로 구현 완료를 판정하지 않는다. 특정 출판사의 사전·음성·문제집은 기능 재현과 콘텐츠 확보를 나누어 검토한다. 확보하지 못한 콘텐츠나 물리적 주변기기 의존 기능을 몰래 다른 것으로 대체하지 않고 미해결 항목으로 남긴다.

브랜드·기기 디자인·사전 원문·음원·학습 자료의 배포 조건은 별도다. 공식 기종 스킨을 배포하려면 사용할 자료의 권한을 확인한다. Apple은 앱에 직접 제작했거나 사용 권한이 있는 콘텐츠를 포함하도록 요구한다. [App Review 5.2](https://developer.apple.com/app-store/review/guidelines/#intellectual-property)

## iOS 표현과 자산 제작 순서 — 제안

SwiftUI를 네이티브 UI 후보로 검토했다. Context7에서 Apple 문서의 원근 회전·회전축 기능을 확인했다. 정면 위주의 개폐 표현은 레이어 기반으로 먼저 검토하되, 두께·측면·힌지의 입체감이 부족하면 실제 3D 모델을 사용한다. 아직 렌더링 방식이나 최소 iOS 버전을 확정하지 않았다. [SwiftUI 원근 회전](https://developer.apple.com/documentation/swiftui/view/rotation3deffect(_:axis:anchor:anchorz:perspective:))

Higgsfield는 기종 결정 후 재질·조명·개폐 속도 레퍼런스 영상이나 소개 영상이 필요할 때 활용 후보로 알린다. 생성 영상은 편집 가능한 힌지 모델이나 누를 수 있는 UI와 동일하지 않다. 실제 조작 부분은 앱에서 입력에 반응해야 한다. 필요 자산은 닫힌/열린 외형, 치수와 힌지 축, 재질, 키별 음원이며 실제 3D를 선택하면 본체·덮개·키의 분리 모델이 필요하다. 현재 Higgsfield 기능·출력 형식을 검증하거나 토큰을 사용하지 않았다.

실제 iOS 빌드·시뮬레이터·기기 테스트에는 Mac의 Xcode 환경이 필요하다. 현재 Windows에서는 문서 조사와 설계만 진행했다. [Xcode](https://developer.apple.com/xcode/)

## 다음 결정

사용자는 일본 CASIO EX-word, 한국 SHARP 리얼딕·iriver 딕플 계열의 비교 분석에 동의했다. [기종 비교 분석](research/device-comparison.md)에서 XD-SW6400·RD-9100MP·D26·D100을 살핀다. 첫 기준 기종과 제작 순서는 추천 단계이며 아직 확정하지 않았다. 이후 원형 기능 대조표와 현대적 확장 메뉴를 검토해 상세 설계를 작성한다. 여러 기종을 한꺼번에 완전 재현하는 것으로 시작하지 않되, 첫 기종 검증이 최종 전체 범위 축소를 뜻하지는 않는다.
