## 수정 방향

기기를 휴대폰 안에 작게 놓는 구성을 기본 사용 화면으로 채택하지 않는다. 본체의 실버 재질·힌지·LCD·버튼 인상은 유지하면서 사전 화면과 자주 쓰는 조작을 세로 화면에 맞춰 재배치한다. 실제 기종의 키 배열을 그대로 재현하는 목표와는 차이가 있으므로 확정된 원형 복제라고 설명하지 않는다.

- 실사용 배치: LCD가 본체 높이의 약 60%, 하단 조작 6개의 높이는 49px이다. 검색창을 누르면 기기의 시스템 키보드를 사용한다.
- 원형 배치 비교: 전체 자판이 차지하는 공간과 축소된 LCD를 비교하기 위한 간략한 배치다. 실제 기종의 정밀 재현이 아니다. 기본값으로 추천하지 않는다.
- 기기 외형 감상: 닫힌 덮개와 스킨 선택에서 형태·재질의 차이를 표현한다. 손가락으로 누르는 화면을 장식 사진으로 대신하지 않는다.
- 스킨 변경: 현재 검색어·뜻풀이·저장한 단어를 유지한다. 이 임시 시안은 스킨 선택 즉시 적용한다. 이전 이미지의 미리보기·적용 확정 흐름은 생략했다.

## 조작 범위와 검증

의존성 없는 단일 HTML로 만든 폐기 가능한 배치 검토용 시안이다. 파일을 브라우저로 열거나 프로젝트의 docs/design 폴더를 정적 서버로 제공해 실행할 수 있다. iOS 앱으로 전환하거나 기존 네이티브 우선 방침을 변경한 것이 아니다.

예시 단어 apple·여백·余白만 제공한다. 검색 → 목록 선택 → 뜻풀이, 저장/해제, 단어장, 세 스킨 변경, 덮개 닫기/열기, 두 배치 비교를 조작할 수 있다. 실제 사전 공급원·발음·원음·필기 인식·현실적 3D 모션은 연결하지 않았다. 새로고침하면 저장과 선택 상태가 초기화된다.

브라우저에서 확인한 사항:

- apple 저장 후 SHARP로 바꾸어도 검색어와 단어장 항목이 유지된다.
- 예시에 없는 단어는 임의의 뜻 대신 안내를 표시한다.
- 余白 검색 후 뜻풀이를 열고 원형 배치로 바꾸어도 같은 항목을 보여준다.
- 320 CSS px 폭에서 가로 넘침이 없고, SHARP 실사용 하단 키는 약 84×49 CSS px, 예문은 17 CSS px로 측정됐다.
- 작은 화면에서 비교 전환 막대가 조작부를 가리지 않도록 본체 위로 이동했다.

브라우저의 CSS px 측정이며 iOS의 pt 사용성과 동일한 검증이 아니다. 실제 iPhone의 시스템 키보드 등장 시 화면 크기, 손가락 오입력률, 한 손 사용성, VoiceOver와 글자 확대는 이후 네이티브 시제품에서 확인해야 한다. 실제 사용성 개선을 사용자 테스트로 입증한 상태는 아니다.
